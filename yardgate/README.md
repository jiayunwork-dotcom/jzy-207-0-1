# YardGate — 堆场地基应力准入服务

内河集装箱码头堆场调度的一道"地基关"：每一次落箱、提箱、翻箱在执行前先
核算黏土层顶面的竖向附加应力，任一检查点超过该点允许值就整笔拒绝。

- 语言 Go 1.22，Web 框架 Gin，事件与快照落 PostgreSQL 16
- 地基按弹性半空间，地表荷载的竖向附加应力按 Boussinesq 集中力解叠加
- 对外只有 HTTP 接口

## 运行

```bash
docker compose up --build
# 服务监听 :8080，数据库 postgres:16-alpine，首次启动自动建表
```

本地开发：`go test ./...`（`-short` 跳过 10 万笔一致性测试）。

## 物理模型与荷载离散

集中力解（z 为检查点深度，r 为水平距离，P 为地表集中力）：

```
σz = 3·P·z³ / ( 2π·(r²+z²)^(5/2) )
```

核对值（`internal/stress/stress_test.go`）：100 kN、2 m 深处正下方
11.94 kPa，水平偏离 1.5 m 处 3.91 kPa。两条必须成立的关系都有测试：
叠加性（多荷载共同作用 = 各自作用之和）与平面积分（任一深度水平面上
σz 的面积分 = 地表荷载总和，数值积分误差 < 0.2%）。

**离散方式**：堆位底面（矩形 a×b）上的箱重按均布荷载处理，划分成
m×n 个等大子块，每块用其形心处的集中力代替（力矩法/中点法则）。
距堆位中心超过 `far_field_factor` 倍底面对角线的检查点直接用整块
一个集中力（远场近似），近处按 `max_cell_size_m` 细分。多层堆位按
层数×单箱重合成总荷载作用在同一底面上（不模拟四角件点传力——堆场
地坪整体浇筑，荷载在板内已扩散，底面尺度的均布假设更贴近设计惯例）。

**误差量级**：中点法则对光滑影响函数是二阶的，相对误差 ≈ C·(s/z)²，
s 为子块边长、z 为深度。实测（6×2.4 m 堆位、900 kN、z=2 m 的最不利
浅层情形）：s=z/4 时峰值点误差约 0.5%；每加密一倍误差约缩为 1/4
（渐近区实测收缩比 ≈4）。默认参数 s=1 m、z=12 m 时 (s/z)²≈0.007，
峰值误差约 0.05%，远小于允许值的不确定度。远场单点近似误差
O((diag/r)²)，r>4·diag 时 <1%，且只影响远小于允许值的尾部贡献。
收敛性由 `TestDiscretizationConvergence` 保证：1×1、2×2、…、128×128
单调收敛到同一极限（Richardson 外推吻合到 1e-3 kPa 以内），与初始
划法无关。

**截断**：单块贡献 < `cutoff_kpa`（默认 1e-6 kPa）的检查点不计入。
每个荷载被忽略的贡献都小于该阈值；相对几十 kPa 的允许值可以忽略，
且重放用同一确定性算法，不影响一致性指标。

## 状态维护：增量 + 快照（为什么不定期全量重算）

选择**增量维护**：每笔生效作业只把它的贡献加到检查点网格上，每
`snapshot.interval_events`（默认 1000）笔异步落一次快照（网格值 +
各堆位层栈），重启时用最近快照 + 其后事件重放恢复。

理由：增量与重放执行的是**同一序列的同一批浮点运算**（同样的离散、
同样的截断、同样的加法顺序——重叠区域由分片锁串行化保证顺序，不重叠
区域写不同的数组元素、天然可交换），所以两者逐位一致，不存在浮点
漂移；而全量重算每笔要 O(事件数×检查点数)，十万笔后不可行。

**实测偏差**：`TestIncrementalMatchesReplay100K` 连续执行 100,000 笔
随机落/提/翻后，增量维护的网格与从空场全量重放的最大偏差为
**0 kPa**（逐位相同，要求 ≤1e-6 kPa）；经快照 + 尾部重放的恢复路径
同样 0 kPa。

## 作业准入与并发控制

- 每笔作业先算**影响域**：各涉及堆位中心 ± 影响半径 R（由荷载大小、
  深度、截断阈值反解 Boussinesq 公式得到）覆盖的检查点分片
  （16×16 点一片）。
- 作业按分片 id 升序锁住自己全部影响域分片（固定顺序，无死锁），
  在锁内：重新规划（层数校验、荷载计算）→ 计算增量 → 逐点判定
  （现值+增量 ≤ 允许值）→ 生效（改堆位层栈、加增量、分配事件号、
  同步写事件表）。判定不过就整笔拒绝，网格不变，返回超限最严重的
  5 个点及超出量。
- **相邻箱区**：两笔作业影响域相交 ⇒ 共享分片 ⇒ 串行，后到的能看到
  先到的已生效荷载，于是"各自不超、合起来超"时恰有一笔生效
  （`TestConcurrentAdjacentBlocksSingleWinner`，30 轮并发验证）。
- **不相邻箱区**：影响域不相交 ⇒ 无共享分片 ⇒ 真正并行、互不等待
  （`TestConcurrentDisjointBlocksNoBlocking`：一笔作业停在临界区内，
  远处作业照常完成）。
- 事件号在分片锁内、写库成功后单调分配（无空洞）；更正与快照取
  引擎级写锁，与所有作业互斥。
- 提箱/翻箱的荷载从堆位层栈（每箱记重量与来源事件号）推出；翻箱 =
  一笔作业内源堆位减、目的堆位加，合并判定。

## 事件、重放与历史查询

- 每笔生效作业/更正写一条事件（PG `events` 表，含作业参数与冗余的
  荷载变化明细），按生效顺序编号。
- `GET /api/grid/at/:seq`：最近 ≤seq 的快照 + 其后事件的荷载明细
  重放，得到当时的网格。
- 启动恢复：最近快照 + 忠实重放其后全部事件（重放重新规划、重新
  离散，与在线路径共用同一状态机）。

## 称重更正

`POST /api/corrections {target_seq, new_weight_kn}`：

1. 只接受落箱事件为更正对象；新箱重必须为正。
2. 更正本身也过准入：该批箱**仍在场上**的部分按重量差产生荷载增量，
   若使当前网格超限则整笔拒绝（已离场的箱不产生增量）。
3. 更正作为新事件记录，不改写历史事件。
4. 返回**影响清单**：在更正后的数据下（该落箱事件自始按新箱重计，
   历史上其他更正照常生效），从目标事件之后重放，逐笔重新判定，
   列出会被拒绝的已生效作业编号。反事实重放优先从不含该更正影响的
   最近快照开始，否则从空场开始。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/jobs` | 提交作业。落箱 `{type:"place",block,bay,row,weight_kn,tiers}`；提箱 `{type:"remove",...,tiers}`；翻箱 `{type:"reshuffle",...,to_block,to_bay,to_row,tiers}`。200 `{accepted,seq}`；409 `{accepted:false,violations:[{x,y,stress_kpa,allowance_kpa,excess_kpa}]}`；400 字段错误（`field` 指明字段） |
| POST | `/api/corrections` | 更正箱重 `{target_seq,new_weight_kn}` → `{accepted,seq,affected_seqs}`；409 超限；400 字段错误 |
| GET | `/api/grid/current` | 当前网格（含 seq、几何、逐点应力） |
| GET | `/api/grid/at/:seq` | 指定事件号之后的网格 |
| GET | `/api/events?from=&to=` | 事件列表 |
| GET | `/api/health` | 健康检查 |

拒收并指明字段的情形：箱重不为正（`weight_kn`）、层数超过堆位允许
层数或不为正（`tiers`）、提箱层数超过堆位现有层数（`tiers`）、未知
堆位（`slot`）、未知作业类型（`type`）、更正目标不存在或非落箱事件
（`target_seq`）、新箱重不为正（`new_weight_kn`）。配置加载期拒收：
检查点深度不为正、允许值不为正、堆位尺寸不为正、堆位互相重叠。

## 代码结构

```
cmd/server            入口：加载配置、连库、恢复状态、起 HTTP
internal/config       配置加载与校验
internal/stress       Boussinesq 解、影响半径、荷载离散（应力计算 + 荷载离散）
internal/yard         箱区/堆位模型与静态校验（尺寸、重叠）
internal/grid         检查点网格、允许值分区、增量计算与超限评估
internal/admission    作业准入与并发控制：状态机、分片锁、引擎、更正、重放原语
internal/events       事件存储（PostgreSQL / 内存）与快照
internal/httpapi      Gin HTTP 层
```

## 测试覆盖

- 两个核对值（11.94 / 3.91 kPa）
- 叠加性与平面积分（数值积分 = 荷载总和）
- 离散细分收敛（二阶收敛到同一极限）
- 超限拒绝后网格不变、无事件号
- 增量 vs 重放：10 万笔后最大偏差 0 kPa（含快照恢复路径）
- 跨箱区边界并发作业只生效一笔（30 轮）
- 不相邻箱区并发不阻塞（临界区驻留验证）
- 历史事件编号查询（含快照加速路径）
- 称重更正影响清单（含箱已离场、快照回退/复用、更正超限拒绝）
- 全部测试在 `-race` 下通过
